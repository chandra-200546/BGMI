# NexBattles BGMI Tournament Platform

A premium BGMI esports tournament management web application built with TanStack Start, React, TypeScript, Tailwind CSS, shadcn/ui primitives, Lucide icons, Recharts, React Hook Form, and Zod-ready architecture.

The current build is a production demonstration surface with complete public, captain, and admin workflows represented in the UI, plus a PostgreSQL Prisma schema for the backend domain model.

## Included

- Tournament discovery with filters, status badges, slots, prize pools, entry fees, maps, and CTAs
- Six-step team registration flow: tournament, team details, captain, roster, payment proof, review
- Live leaderboard with automatic total points: placement points + finish points - penalties
- Match schedule, room release vault, QR check-in state, and protected credential messaging
- Captain dashboard with registration timeline, roster lock, notices, penalties, downloads, and transfers
- Drop-location strategy map, charted statistics, map distribution, and scoring rules
- Announcements, rules library, gallery, hall-of-fame style media sections, and contact footer
- Admin console for tournaments, registrations, results, penalties, transfers, seasons, exports, and audit logs
- Prisma schema covering users, roles, tournaments, teams, players, registrations, payments, matches, rooms, results, leaderboards, drops, announcements, notifications, penalties, appeals, transfers, check-ins, media, hall of fame, sponsors, rules, audit logs, and API keys
- Environment example for PostgreSQL, sessions, uploads, payments, email, Discord, and WhatsApp support

## Local Development

```bash
npm install
npm run dev
```

The dev server runs with Vite/TanStack Start. Open the local URL printed by the terminal.

## Production Build

```bash
npm run build
```

## Database

Copy `.env.example` to `.env` and set `DATABASE_URL` to a PostgreSQL connection string.

```bash
npx prisma generate
npx prisma db push
```

The Prisma schema is in `prisma/schema.prisma`. Sensitive room credentials are modeled separately in `MatchRoom` and should only be returned to approved teams after `releaseAt`.

## Deployment To Vercel

1. Create a PostgreSQL database through Neon, Supabase, Vercel Postgres, or another managed provider.
2. Add the environment variables from `.env.example` in Vercel Project Settings.
3. Use these build settings:
   - Install command: `npm install`
   - Build command: `npm run build`
   - Output: generated by TanStack Start/Nitro
4. Deploy:

```bash
npx vercel --prod
```

## Public API Plan

The schema supports read-only endpoints such as:

- `GET /api/public/tournaments`
- `GET /api/public/tournaments/:id`
- `GET /api/public/leaderboard/:tournamentId`
- `GET /api/public/teams`
- `GET /api/public/teams/:id`
- `GET /api/public/schedule/:tournamentId`
- `GET /api/public/announcements`

Use `ApiKey` for hashed API keys, per-key rate limits, pagination, filtering, and audit logging.

## Security Notes

- Enforce role-based access for captain and admin routes server-side.
- Hash passwords and API keys.
- Validate all forms with Zod.
- Validate file uploads by MIME type, extension, size, and image dimensions.
- Never expose `MatchRoom.password` through public APIs.
- Keep all admin actions in `AuditLog`.
- Prevent duplicate team names per tournament and duplicate match results through database constraints.
